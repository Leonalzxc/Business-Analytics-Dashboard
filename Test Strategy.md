# Стратегия тестирования
## Business Analytics Dashboard

## 1. Цель и область

Целью стратегии тестирования является обеспечение качества кода, надежности системы и корректной работы всех компонентов приложения. Стратегия охватывает:

- Unit тестирование отдельных компонентов
- Integration тестирование взаимодействия между модулями
- E2E тестирование полных пользовательских сценариев
- Performance тестирование
- Security тестирование

## 2. Виды тестирования

### Unit тесты (модульное тестирование)

Тестирование отдельных функций, методов и компонентов в изоляции.

#### Backend (Python + Pytest):

- Тесты для auth.py (валидация пароля, генерация JWT токена)
- Тесты для models (создание, обновление, удаление записей)
- Тесты для services (бизнес-логика)
- Тесты для API schemas (валидация данных)

#### Frontend (React + Jest):

- Тесты компонентов (props, state, события)
- Тесты Redux reducers (изменение состояния)
- Тесты utility функций (форматирование, валидация)

### Integration тесты

Тестирование взаимодействия нескольких компонентов между собой.

#### Backend:

- Тесты API endpoints (POST, GET, PUT, DELETE)
- Тесты подключения к БД
- Тесты взаимодействия auth + dashboards (защита маршрутов)

#### Frontend:

- Тесты интеграции Redux с компонентами
- Тесты API клиента
- Тесты форм с валидацией

### E2E тесты (end-to-end)

Тестирование полных пользовательских сценариев.

#### Примеры сценариев:

- Пользователь регистрируется → логинится → создает дашборд → добавляет график → сохраняет
- Импорт CSV файла → загрузка данных → отображение в таблице
- Экспорт дашборда в PDF

## 3. Инструменты и фреймворки

### Backend:
- **Pytest** - основной фреймворк
- **pytest-cov** - для расчета покрытия
- **fixtures** - для подготовки данных

### Frontend:
- **Jest** - unit тесты
- **React Testing Library** - тесты компонентов
- **Cypress** или **Playwright** - E2E тесты

## 4. Метрики и целевые показатели

- Покрытие кода тестами: минимум 80%
- Время выполнения unit тестов: < 5 минут
- Время выполнения integration тестов: < 10 минут
- E2E тесты: все критические сценарии должны быть покрыты

## 5. График тестирования

- **Unit тесты**: на каждый коммит (CI/CD)
- **Integration тесты**: перед merge в develop
- **E2E тесты**: перед release
